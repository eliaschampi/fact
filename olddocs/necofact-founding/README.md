# necofact.pe — Documentación fundacional (archivo)

> Archivo (2026-08-23, mañana). El sistema vivo de documentación es el trío
> `README.md` / `SPEC.md` / `TASK.md` en la raíz del repo. Esta carpeta conserva
> la fundación original como referencia profunda para V1–V12.

NecoFact es un sistema de ventas con facturación electrónica SUNAT: CPE `01`/`03`/`07`
y GRE remitente `09`. La operación comercial existe para producir un documento
electrónico correcto, recuperable y corregible.

## Contenido de esta carpeta

| Archivo | Qué conserva |
|---|---|
| `NOTE.md` | Este contexto |
| `plan.md` | Plan técnico de origen completo (copia fiel de `~/Downloads/plan.md`) |

| `requirements.md` | Ledger completo FR-*/NFR-* con IDs estables |
| `foundation.md` | Reglas FDN-0..17: stack, layout, semántica, invariantes exactos |
| `task.md` | Verticales V0–V12 con tareas y criterios de hecho detallados |

## Por qué importa para las sesiones futuras

El `SPEC.md` de la raíz condensa la ley, pero aquí vive el detalle que V3–V5
necesita textual: la mecánica exacta de los advisory locks de Faztore, el delta
condicional de inventario, la idempotencia `request_key` de Coedula, el contrato
del binario PDF, y los ~70 requisitos con ID para verificar "hecho".
